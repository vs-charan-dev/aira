Build a Memory Palace module inside AIRA using the following information.

GOAL
The Memory Palace represents long-term personal memory visually as different rooms.

The user should be able to:
1. Enter a room and browse memories.
2. Search memories using natural language.
3. Ask questions such as:
   "What package am I targeting?"
   "What did I learn from my previous hackathons?"
   "Which city do I prefer for jobs?"
   "Why do I prefer simple architectures?"
4. Receive an answer generated only from relevant stored memories.
5. See exactly which memories were used to generate the answer.

IMPORTANT:
Do not store the following information as one giant document.

Every fact, preference, decision, goal, person, project, event or lesson should be stored as an individual memory object.

Each memory should have approximately this structure:

{
  "id": "CAREER-001",
  "room": "Career Room",
  "category": "career_goal",
  "title": "Target Role",
  "memory": "Charan wants to become an AI Engineer or AI FTE.",
  "importance": "high",
  "tags": ["career", "AI", "jobs"],
  "source": "Memory Palace Seed",
  "created_at": "2026-10-09"
}

IDs should follow the room.

Examples:
IDENTITY-001
ACADEMIC-001
CAREER-001
PROJECT-001

PERSON-001
DEV-001

GOAL-001

When multiple memories support an answer, return all supporting references.

Example:

User:
"Where do I want to work and what package am I targeting?"

AIRA:
"You currently prefer working in Hyderabad and your target minimum package is approximately ₹24 LPA.

Memory References:
Career Room → CAREER-002
Career Room → CAREER-003"

If the information does not exist in memory, DO NOT invent an answer.

Say:
"I don't currently have a memory about that."

MEMORY RETRIEVAL RULES
==================================================

When the user asks a question:

1. Convert the question into a semantic query.
2. Retrieve the most relevant memories.
3. Prefer highly relevant memories over simply retrieving many memories.
4. Answer only using the retrieved memories.
5. Never fabricate missing personal information.
6. Show the memory references used.
7. If memories conflict, explicitly mention the conflict.
8. Allow the user to correct a memory.
9. Keep the previous version in an audit/history field if possible.
10. Allow memories to be marked:
   - active
   - outdated
   - uncertain
   - superseded

IMPORTANT SAFETY / ACCURACY REQUIREMENT
==================================================

The Memory Palace should distinguish between:

FACT:
Directly stated by the user.

INFERENCE:
A conclusion generated from multiple facts.

UNKNOWN:
Information that does not exist.

Never present inference as stored fact.

For example:

Stored fact:
"Charan targets ₹24 LPA."

Allowed inference:
"Because Charan targets ₹24 LPA and major MNCs, high-paying AI roles may align with his career goals."

The second statement must be labeled as an inference.

Do not store passwords, OTPs, API keys, banking credentials or other secrets.
